# E04：Jetson Orin NX 上 YOLO26s TensorRT 推理链路优化阶段报告

日期：2026-10-22（Asia/Hong_Kong）。状态：本轮组合正确性与30组正式性能已回收审查；用户要求暂停后续实验。B5长期稳定性及生产采用未验收，本报告不将E04全阶段标记为完成。

## 1. 主要结论

本轮同条件、固定相机有球系统中，原始路径R0为 **14.580 Hz**，A2合并结果回传为 **15.100 Hz**，A2+CUDA Graph（R4）为 **15.590 Hz**。R4三轮配对processing Hz提升 **6.928%**，读取完成至发布平均节省 **4.454 ms**；相对同期A2再提升 **3.246%**，三个重复方向一致。当前最值得保留的工程研究候选是 **A2+Graph**，尚未批准长期生产运行。两目测量/跟踪有效率存在现场差异，物理定位精度未独立验收。

A2+Graph+缓冲复用（R5）平均 **15.710 Hz**，相对R0宏平均 **+7.748%**；但相对R4的三轮增量为 **+1.610% / −0.218% / +0.911%**。C2的局部预处理节省可重复，系统增量未在三轮全部复现，因此继续保留开关，不默认纳入推荐组合。

模型、Engine、640输入、batch2、类别、conf/IoU/top-k、外部NMS、双目定位/跟踪及ROS协议没有因候选而改变。NMS仍为原Torch fallback，未实现新的CUDA NMS。本轮没有训练、网络修改、GPU Resize、异步队列、双缓冲或功耗/频率档位对比。

### 代码实现与边界

- **A1**：只简化CPU候选构造；收益不稳定，不保留为主候选。
- **A2**：原NMS及坐标恢复之后，将左右目全部最终六列框合并为一次blocking GPU→CPU回传，再保留原候选构造、排序和top-k。top-k不提前，阈值不增加。
- **A3**：确认Torchvision C++扩展存在ABI undefined symbol；没有兼容替代通过验收，不全局升级Torch/Torchvision/CUDA，原NMS继续使用。
- **Graph**：独立TensorRT context、稳定GPU输入/输出和独立stream；每次更新当前输入后Replay，输出在图外clone，避免NMS原地改写或下一帧覆盖旧输出；保留原执行路径及可检测回退。
- **C1/C2**：完成八段方法墙钟诊断；C2保留OpenCV Resize/Letterbox和原blocking传输，复用2457600B uint8 BCHW host缓冲及tensor view，GPU FP32输出仍按调用独立。

隔离候选源提交为`e0672063ed58446a9ed3ecec59ad854380f5795b`，原benchmark参考提交为`de01d53744df064d6c551b99cff3b68f5bbd6d20`。phase4/source的30份源/config/package与phase1相同；phase5只增加冻结排程和观测工具，具体文件以manifest SHA为准。主仓库未提交或推送，保留用户原有改动。

## 4. 本轮设计、中断与统计方法

每个有效作业100次预热、60秒测量。每scope三轮，每轮5项首尾R0；候选顺序分别为A2→R4→R5、R5→A2→R4、R4→R5→A2。A2同期对照用于识别Graph增量，R5对R4识别C2增量。

机器人低电量时正常停止本测试。15个detector组成完整三块保留；system第一块4项完成但末R0中断。充电重启后，原4项标superseded、原失败及文件保留，system整块重跑，再完成三轮系统采集。最终35个attempt中只有30个complete纳入统计，4个superseded和1个failed排除。未将跨重启的首尾基线拼成同一个块。

有效system测量窗口按UTC、重启会话和逐帧cycle范围对齐，共897个遥测样本，全部408MHz，GPU温度50.781～52.625°C。固定图CSV没有绝对时间戳，只能给含初始化/预热的整job遥测：1197样本、306/408MHz、43.750～49.437°C，不将它伪装成精确测量期频率。

本轮六个R0块首尾漂移：detector **1.901% / 0.916% / 0.938%**，system **1.168% / 2.056% / 0.497%**，均低于预设3%停止阈值。此阈值不是统计显著性保证，也不是最小可检出收益；较小增量还需看三轮方向和尾部。

下表绝对值按各有效作业原始帧池化；processing Hz用有效cycle窗口的帧数/时长，publish Hz用发布间隔定义，不取平均cycle的倒数，也不乘2。相对收益按三轮等权宏平均：每轮候选对首尾R0指标算术平均；直接增量比较同轮A2/R4/R5。P95/P99的配对参照为首尾分位数平均，与池化基线分位数不同；时间插值仅作敏感性分析。只有3个独立重复，不把数万帧当作独立实验重复。

GPU事件、异步方法墙钟和系统墙钟分别解释，不相加。phase5没有重新测纯Engine CUDA event，不将阶段0的28.136ms或Graph约0.89ms的异步inference方法时间填成组合Engine实测。

## 6. 正确性、系统可用性与风险

61对Val包含小目标、遮挡、模糊、无球等开发样本；单项及组合对比覆盖预处理、原始输出、最终框数量/坐标/分数/类别/顺序、左右目归属、双目选择、三维测量、跟踪和7字段ROS payload。组合732数组精确一致；全部使用确定性回放时钟和冻结内参。这证明被测样本实现等价，不是全量AP或物理距离精度评估；稠密/同分/边界等另有CPU专项，不能据每目常见1–2框保证所有负载性能。

12个有效Graph作业均每进程capture=1，warm100、最终replay/update/clone=100+N、zero fallback、restore完整；C2的6个有效作业均host/view各1次分配且每次成功。A2原NMS不变，实际一次合并回传计数和字节与逐帧记录核对通过。恢复钩子成功与60秒无明显增长不能替代B5，也不能证明长期无显存泄漏。

本轮新增只读packet标量观察，不改变原payload、帧关联或ROS协议，不增加Tensor访问或CUDA同步。观察字段包括frame_idx、source读取相对时间戳、measurement_valid、tracking_valid、initialized、coasting和frames_since_measurement；逐帧计数、递增与恢复通过。

## 7. 为什么与原来约17Hz不同

| 数据来源 | 原路径processing Hz | 条件与适用范围 |
|---|---:|---|
| E03现场锚点 | 16.812 | 一轮30秒，Viser开启；当时画面/持续有球情况不能擅自补填 |
| E04阶段0现场 | 18.610 | 当前冻结配置，Viser关闭；与后续有球场景不同 |
| E04无球专项 | 18.591 | 几乎全空，不能替代有框回传/定位负载 |
| E04上一有球单项 | 14.861 | 同期A2为15.572Hz，配对约+4.786% |
| 本轮有球组合R0 | 14.580 | 新packet观察和充电重启后的现场；同期R4为15.590Hz |

原来约17Hz的记录有效。画面、候选和跟踪状态、背景负载、热态及观测工具跨阶段并不完全一致，尚未逐项做因果分解。因此本报告只声称本轮同条件 **14.580→15.590Hz** 的配对收益，不声称原17Hz已提升到更高，也不把不同场景17→15.590解释为优化后变慢。

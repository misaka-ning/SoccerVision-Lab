# 机器人足球视觉感知系统模型优化与部署性能阶段成果报告

**报告日期：** 2026 年 10 月 23 日  
**项目方向：** 机器人足球目标检测、双目视觉定位与 Jetson Orin NX 边缘部署  
**项目状态：** 四个模型版本已完成训练与验证，部分部署优化已完成实机测试，最终模型方案待确认

## 一、工作概述

本阶段工作围绕机器人足球视觉感知系统的目标检测准确率、实时推理效率和边缘端运行稳定性展开。

系统采用 ZED Mini 双目摄像头采集图像，通过 YOLO26 检测足球目标，结合左右目检测结果完成双目匹配和三维空间定位，并将结果发送至机器人运动控制系统。

初期采用 YOLO26s 单类别检测模型，实际检测效果较好，但在 Jetson Orin NX 上运行时，双目目标检测与推理链路的耗时限制了系统更新频率。

针对这一问题，本阶段主要完成了以下工作：

1. 完成 YOLO26s 与 YOLO26n 单类别足球检测模型的训练和对比。
2. 基于 YOLO26s 教师模型，探索 Nano 模型的直接知识蒸馏与分阶段知识蒸馏。
3. 对 TensorRT 推理链路进行性能剖析，定位主要计算及数据处理开销。
4. 优化双目检测结果的数据回传方式，并引入 CUDA Graph。
5. 在 Jetson Orin NX 上验证不同模型及功耗模式下的运行表现。

目前形成了四个可供选择的模型版本，分别在检测精度、困难场景召回率、误报控制及推理效率方面具有不同特点。

## 二、模型训练与优化成果

### 2.1 四个模型版本

| 模型 | 网络 | 训练方式 | 主要定位 |
|---|---|---|---|
| E01 | YOLO26s | 官方预训练权重 + 足球数据集微调 | 高精度基线 |
| E05 | YOLO26n | 官方预训练权重 + 足球数据集微调 | 轻量化、低误报 |
| E06 | YOLO26n | 官方 Nano 预训练权重 + E01 教师知识蒸馏 | 困难场景高召回 |
| E07 | YOLO26n | E05 权重继续训练 + E01 教师知识蒸馏 | 精度与误报平衡 |

E01 采用规模较大的 Small 网络，具有较强的目标特征表达能力。

E05、E06 和 E07 均采用轻量化 Nano 网络，主要区别在于训练策略，而不是推理阶段增加额外的教师网络。知识蒸馏只在训练阶段使用，部署时仍由 Nano 学生模型独立执行推理。

### 2.2 检测性能对比

所有模型使用同一验证集进行评价，验证集包含 1,223 张图片、855 个真实标注框，其中无球图片 410 张。

Precision、Recall 和 F1 使用固定 `conf=0.45`、匹配 IoU=0.5 的评价口径；mAP 基于完整候选置信度范围计算。

| 模型 | mAP50 | mAP50–95 | Precision | Recall | 无球误报率 |
|---|---:|---:|---:|---:|---:|
| E01 | 96.02% | **78.57%** | 97.10% | 90.06% | 2.93% |
| E05 | 94.17% | 76.85% | **98.91%** | 84.68% | **0.98%** |
| E06 | **96.51%** | 77.19% | 94.27% | **92.40%** | 6.10% |
| E07 | 95.27% | 77.54% | 96.75% | 90.64% | 1.71% |

从结果可以看出：

**E01：高精度版本。** mAP50–95 最高，整体检测精度较好，适合作为对检测质量要求较高的部署方案。

**E05：轻量化低误报版本。** Precision 最高，无球误报率最低，但 Recall 相对较低，更适合对误检敏感、能够容忍一定漏检的场景。

**E06：高召回版本。** Recall 达到 92.40%，对远距离小目标和遮挡目标的检测表现突出，但无球误报明显增加，需要考虑误报对机器人定位系统的影响。

**E07：综合平衡版本。** Recall 达到 90.64%，接近 E01，同时无球误报率低于 E01，是当前值得优先进行综合部署验证的 Nano 模型。

### 2.3 困难场景检测对比

| 场景 Recall | E01 | E05 | E06 | E07 |
|---|---:|---:|---:|---:|
| 远距离小目标 | 86.17% | 79.79% | **92.34%** | 88.51% |
| 局部遮挡 | 80.07% | 70.11% | **82.29%** | 76.02% |
| 运动模糊 | 86.16% | 80.80% | 90.18% | **90.63%** |

E06 对远距离小目标和局部遮挡具有明显优势；E07 在运动模糊场景下表现最好，同时误报控制优于 E06。

上述结果说明，知识蒸馏有助于改善部分轻量化模型的检测表现，但不同蒸馏策略对应不同的精度与误报取舍。

需要注意，E07 从已经微调完成的 E05 权重继续训练，其性能变化同时受到额外训练和蒸馏的影响，目前不能将全部提升单独归因于知识蒸馏。

## 三、系统推理链路优化

### 3.1 原始系统运行方式

原始系统采用左右目组成 batch=2 的方式进行 TensorRT 推理，检测后分别处理左右目候选框，再完成双目匹配、三维定位和 ROS 发布。

原有实现存在以下性能开销：

- 左右目检测结果存在重复 GPU→CPU 回传及相关同步操作。
- TensorRT 推理需要重复提交多个 CUDA Kernel。
- 检测后处理采用 PyTorch NMS fallback，存在较高的张量处理开销。
- CPU 图像预处理包含 Resize、Letterbox、颜色转换及 Tensor 数据整理。
- 高分辨率特征计算和中间数据复制占用一定 GPU 执行时间。

通过 TensorRT 逐层 Profiling 和 Nsight Systems 分析，进一步确认了 Backbone、Neck、辅助数据复制以及推理前后处理的性能成本。

### 3.2 已完成的优化措施

**（1）TensorRT FP16 部署**

将 YOLO 模型转换并部署为 TensorRT Engine，利用 TensorRT 进行网络算子优化，并允许内部使用 FP16 高效计算。

在推理图中，已完成 Conv–BN 融合及未使用检测分支清理。

**（2）双目结果合并回传（A2）**

优化前，左右目最终检测结果分别由 GPU 回传 CPU。

优化后，在保留原 NMS、坐标恢复和候选选择语义的前提下，将左右目最终检测框合并为一次 GPU→CPU 阻塞回传，再在 CPU 端恢复左右目结果。

该方案主要减少重复数据传输调用和同步开销，不修改网络结构，也不改变检测阈值。

**（3）CUDA Graph**

针对固定 batch=2、640×640 的推理配置，使用 CUDA Graph 捕获 TensorRT 的 GPU 执行流程。

后续推理通过更新固定 GPU 输入缓冲区并执行 Graph Replay，减少 CPU 重复提交 GPU Kernel 的开销。

该优化不改变模型参数量和 FLOPs。

**（4）硬件功耗模式对照**

分别观察 Jetson Orin NX 在 25W 与 MAXN 模式下的运行表现。

MAXN 模式下，设备允许使用更高的 GPU 频率上限，实际系统观测频率有明显提升。

需要说明，MAXN 属于硬件运行配置调整，与模型结构优化和推理代码优化分别统计。

### 3.3 部署优化的正式实验收益

针对固定有球场景，在 25W、Viser 关闭的相同条件下，完成 A2 与 CUDA Graph 的组合对照实验。

| 优化版本 | 完整系统频率 | 读取完成至发布平均延迟 |
|---|---:|---:|
| R0 原始链路 | 14.580 Hz | 63.943 ms |
| A2 合并回传 | 15.100 Hz | 61.548 ms |
| R4 A2 + CUDA Graph | **15.590 Hz** | **59.491 ms** |

三轮配对统计表明：

- A2 单独使系统吞吐率平均提升约 **3.57%**。
- A2 + CUDA Graph 组合使系统吞吐率提升约 **6.93%**。
- 组合方案平均缩短读取完成至发布延迟约 **4.45 ms**。
- 在该测试条件下，组合方案的平均、P95 和 P99 延迟均得到改善。

该实验表明，减少重复结果回传和 GPU 任务提交开销，能够在不更换模型的前提下改善机器人视觉系统的运行效率。

### 3.4 已测试但未采用的优化

除有效优化外，还开展了以下实验：

| 方案 | 结果 | 处理决定 |
|---|---|---|
| CPU 候选构造简化 | 未获得稳定收益 | 不采用 |
| CPU 打包缓冲区复用 | 局部收益存在，系统级收益不稳定 | 暂不默认启用 |
| Canvas 复用 | 未获得预期加速 | 不采用 |
| C3k2 局部通道缩窄 | 理论计算量减少，但实机 Engine 未加速 | 保留实验结论，不采用 |
| 更换高性能 NMS | 尚未完成兼容实现验收 | 后续候选 |

其中，C3k2 缩窄实验发现，局部结构变小后 TensorRT 可能选择不同的执行策略，并引入额外的辅助执行开销。因此，理论 FLOPs 降低不一定对应真实硬件推理延迟下降。

这些实验为后续有针对性的模型结构改进提供了依据。

## 四、机器人实际运行表现与交付方案

### 4.1 当前部署情况

目前四个模型版本可以作为不同部署需求的候选。

E01 使用较大的 YOLO26s 网络，当前机器人运行观测约 22 Hz，主要优势是 mAP50–95 较高，适合优先保证检测精度的场景。

E05、E06、E07 均为 Nano 网络，在同类部署配置下预计具有相近的计算性能；目前需要将各自独立的正式测速结果与对应 Engine 绑定归档。

其中，E07 已在以下配置下完成现场运行观察：

- Jetson Orin NX 16GB
- TensorRT FP16
- 双目 batch=2
- 每目输入 640×640
- A2 合并回传及 CUDA Graph 启用
- Viser 可视化关闭

观察到的 ROS 接收频率为：

| 运行模式 | E07 现场观测 |
|---|---:|
| 25W | 约 30～31 Hz |
| MAXN | **约 33 Hz** |

以上频率属于实际运行时的消息频率观察，不代表已经完成四模型完全相同条件下的正式配对 A/B 测试。

### 4.2 模型交付建议

| 使用需求 | 建议版本 | 主要原因 |
|---|---|---|
| 优先检测精度 | **E01** | mAP50–95 最高，Small 模型表达能力较强 |
| 优先低误报 | **E05** | Precision 最高，无球误报率最低 |
| 优先困难场景召回 | **E06** | 小目标、遮挡场景 Recall 最高 |
| 兼顾精度和实时性 | **E07** | Nano 推理效率与较好的综合检测表现 |

四个版本不需要同时部署。可根据足球场景、运控策略、误报容忍程度和实时性要求选择其中一个。

## 五、阶段成果与待完成事项

本阶段已经完成：

1. 四个模型版本的训练及统一验证集对照。
2. YOLO26s 与 YOLO26n 的轻量化方向探索。
3. 两种知识蒸馏训练路径的实验对比。
4. TensorRT 逐层性能剖析及部署瓶颈定位。
5. A2 合并回传与 CUDA Graph 的代码实现及正式组合性能验证。
6. E07 Nano 模型在机器人上的实际运行验证，观察到 30 Hz 以上的 ROS 消息频率。

后续仍需完成：

1. 四模型在相同硬件、功耗、可视化和后处理条件下的正式系统性能对比。
2. A2 + CUDA Graph 的长期稳定性测试和正式生产部署验收。
3. 四模型的实机三维定位准确性与连续定位稳定性评估。
4. 根据最终任务需求确定默认部署模型，并归档对应 Engine、配置和可复现测试记录。

## 六、总结

本阶段围绕机器人足球视觉感知任务，完成了从高精度 YOLO26s 模型到轻量化 YOLO26n 模型的训练、蒸馏和部署验证，并通过 TensorRT 性能分析确定了系统的主要推理及数据处理开销。

在部署层面，采用双目检测结果合并回传与 CUDA Graph 优化，使同条件有球场景的系统吞吐率获得约 6.93% 的提升。进一步使用轻量化 Nano 模型并结合 Jetson Orin NX 的运行模式调整，当前已在 E07 部署中观察到约 30～33 Hz 的 ROS 消息频率。

目前可以提供四个具有不同精度、召回率及误报特点的模型版本，为后续根据机器人实际比赛需求选择部署方案提供了依据。

下一阶段的重点是完成统一条件下的四模型实机对照与长期可靠性验证，并在保持双目定位准确性的前提下，进一步提高系统实时性。

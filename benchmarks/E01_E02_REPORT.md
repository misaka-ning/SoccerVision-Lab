# E1 单类别微调与 E2 结构缩窄实验报告

记录日期：2026-10-21。本文中的 E1、E2 分别对应 `E01_baseline`、`E02_c3k2`。

**E1 建立了足球单类别检测基线，明显改善了原模型的召回和 AP，但低工作阈值下的误报增加。E2 从 E1 权重出发，仅缩窄第 19 层 C3k2 的内部通道，恢复训练后整体 Val 精度接近 E1，总参数量减少约 0.674%；在 Jetson Orin NX 16GB 的三轮交错重复测试中，没有取得可测量的推理延迟或系统吞吐收益。**

## 实验数据与训练条件

两轮实验均使用冻结的 `datasets/v1`：Train 4,346 张，Val 1,223 张。Val 包含 813 张有球图、410 张确认无球图，共 855 个足球框。本文精度均为 Val 结果，不作为独立 Test 成绩。

训练使用 RTX 4060，沿用 Python 3.10.12、PyTorch 2.9.1+cu128、Ultralytics 8.4.173 环境。主要设置如下：

| 项目 | E1 | E2 |
| --- | --- | --- |
| 初始化来源 | E0 原始 YOLO26s 权重 | 已完成训练的 E1 权重 |
| 模型类别 | `nc=1`，`0=football` | 保持 E1 单类别设置 |
| 输入尺寸 / batch / seed | 640 / 8 / 42 | 640 / 8 / 42 |
| 优化器与初始学习率 | AdamW，0.001 | AdamW，0.001，重新建立优化器 |
| 训练预算 | 最多 100 epochs，patience=30 | 相同预算 |
| 其他设置 | AMP、cosine、deterministic，不冻结网络 | 沿用 E1 配方，不冻结网络 |
| 实际训练轮数 | 74 | 78 |
| 最佳 checkpoint 对应 epoch | 44 | 48 |

E2 是从 E1 初始化后进行恢复训练，不是从 E0 重新训练，也不是恢复 E1 的优化器断点。

## E1 完成的工作与结果

E1 将原模型的 80 类检测输出改为足球单类别，迁移兼容权重并完成全网络微调。原模型中的 `sports ball` 类别 32 在评估时映射为足球类别 0；E1 的模型类别直接为 `0=football`。主体仍为 YOLO26s，保留原有多尺度连接与两套检测分支，没有进行结构缩窄。

权重迁移共保留 696/708 个状态张量，重建两个检测分支、三个尺度的 12 个最终分类张量。独立重载 best.pt 后确认 `nc=1`，原始 one-to-many 输出为 `[1, 5, 8400]`，Val 输出类别为 0。

E0 与 E1 的历史公平对照使用完整 Val、CPU 单线程、batch=4、640 方形 letterbox、候选置信度下限 0.001、工作阈值 0.25、匹配 IoU=0.5、NMS IoU=0.7、max_det=300：

| 指标 | E0 原始模型 | E1 单类别微调 | E1 相对 E0 |
| --- | ---: | ---: | ---: |
| mAP50 | 60.2318% | 96.0161% | +35.7843 个百分点 |
| mAP50–95 | 55.4108% | 78.5508% | +23.1399 个百分点 |
| Precision，conf=0.25 | 99.4638% | 94.9275% | −4.5363 个百分点 |
| Recall，conf=0.25 | 43.3918% | 91.9298% | +48.5380 个百分点 |
| F1，conf=0.25 | 60.4235% | 93.4046% | +32.9812 个百分点 |
| TP / FP / FN | 371 / 2 / 484 | 786 / 42 / 69 | 漏检框显著减少 |
| 无球图片误报 | 0/410，0% | 19/410，4.6341% | 误报增加 |

E1 的主要成果是建立了可复现的足球检测基线，并明显改善原模型在该 Val 上的检出能力。代价是 conf=0.25 时误报增加，因此不能称为所有指标全面改善。训练和类别数同时改变，也不能把全部精度收益归因于分类输出维度减少。

历史 RTX 4060 FP32 单次顺序测量中，E0、E1 的 CUDA event 均值约为 6.6431、6.6115 ms，分布高度重叠，原记录未认定为明显加速。该测量不含预处理、传输和 NMS，不能代替 Orin 部署或完整视觉系统成绩。

## E2 完成的工作与结果

### 第 19 层内部宽度缩减

E2 只调整全局编号为 19 的 C3k2，也就是 Head 中的第 9 条顶层定义。编号从 Backbone 的第 0 层连续计算，不按 YAML 文件行号计算。

```yaml
# E1
- [-1, 2, C3k2, [512, true]]

# E2
- [-1, 2, C3k2, [512, true, 0.4375]]
```

| 结构项目 | E1 | E2 |
| --- | ---: | ---: |
| 第 19 层 expansion ratio | 0.5 | 0.4375 |
| 第 19 层输入通道 | 384 | 384 |
| 第 19 层隐藏通道 | 128 | 112 |
| 第 19 层输出，640 输入 | 256 × 40 × 40 | 256 × 40 × 40 |
| 模型总参数量 | 9,948,638 | 9,881,630 |

隐藏通道减少 12.5%，模型总参数量减少 67,008，约 **0.674%**。输入尺寸、足球类别、外部连接尺寸和 P3/P4/P5 检测连接保持原定义。

初始化采用分支感知的确定性前缀通道迁移，同步处理 split、concat、内部支路、残差和 BN 参数，没有执行 L1 排序或重要性评估。选择第 19 层是为了先完成改动范围较小的实验，不代表已经证明它最冗余或最值得剪。

准备阶段完成了迁移、保存重载、官方模型重建及合成前向检查。第 19 层位于 P3 生成之后，但参与 P4 和后续 P5 的生成；恢复训练更新全网络权重，因此不能声称训练后的 P3 数值保持不变。随后由用户完成 78 轮训练，保留最佳 checkpoint 用于独立 Val 和部署比较。

### 恢复训练后的 Val 精度

下表采用当前保留的 E1 原始 run 评估和 E2 在 2026-10-21 完成的独立评估。逐项核对确认，两次评估使用相同的 1,223 张图片及标签内容哈希，AP 核心代码哈希和指标方法一致，均采用 640 方形 letterbox、候选下限 0.001、NMS IoU=0.7、max_det=300、FP32 one-to-many 推理，不启用 TTA。

**E1 历史评估在 CPU，E2 评估在 CUDA 上完成，属于跨设备的历史结果对照，不是严格同环境的配对复测；两次评估的运行耗时不用于速度比较。**

| 指标 | E1 | E2 | E2 相对 E1 |
| --- | ---: | ---: | ---: |
| mAP50 | 96.0161% | 95.9545% | −0.0617 个百分点 |
| mAP75 | 87.0652% | 88.3125% | +1.2473 个百分点 |
| mAP50–95 | 78.5508% | 78.7770% | +0.2262 个百分点 |
| Small mAP50–95 | 72.6731% | 72.8570% | +0.1839 个百分点 |
| Occluded mAP50–95 | 69.1315% | 69.0067% | −0.1248 个百分点 |
| Blurred mAP50–95 | 70.1044% | 72.7565% | +2.6521 个百分点 |

整体 AP 接近，不能描述为“精度完全没有变化”，也不能据此认定缩窄提高了精度。分场景结果并非全部改善，例如遮挡子集的 mAP50 从 90.8935% 降至 89.3997%。场景标签存在重叠，各子集成绩不能相加或简单平均。

E2 在工作阈值 **conf=0.45** 时，Precision=99.1150%、Recall=91.6959%、F1=95.2612%，TP/FP/FN=784/7/71，无球图片误报为 3/410（0.7317%）。E1 上述原始工作点为 conf=0.25，两者的 P/R/F1 和误报数不能直接解释为结构改动带来的提升；AP 使用相同候选下限，与这两个工作阈值不同。

另外，E2 比原 E1 多进行了一轮完整恢复训练。虽然已准备“原 E1 结构继续训练”的同预算 control，目前没有该 control 的训练结果，因此 AP 的微小变化无法与额外训练效应分离。本轮也只有 seed=42，不作多种子稳健性结论。

### Jetson Orin NX 实机性能

按用户提供的实机实验结论记录：

> 在 Jetson Orin NX 16GB 平台上，对两份已有 TensorRT FP16 Engine 进行三轮交错重复测试，结果显示，E2 相比 E1 未取得可测量的推理延迟或系统吞吐收益，说明所测试的结构缩窄方案未能有效改善当前部署条件下的实时性能。

| 项目 | 已确认结果 |
| --- | --- |
| 测试平台 | Jetson Orin NX 16GB |
| 比较对象 | E1、E2 两份已有 TensorRT FP16 Engine |
| 重复方式 | 三轮交错重复测试 |
| 推理延迟 | E2 相比 E1 没有可测量收益 |
| 系统吞吐 | E2 相比 E1 没有可测量收益 |
| 本方案实时性能目标 | 未取得有效改善 |

本次归档的实机信息为上述结论，未附逐轮延迟、吞吐、P95/P99、温度、功耗及 Engine 指纹等原始记录，因而不填写具体毫秒或 Hz 差值，也不据此认定达到 20 Hz、完成双目定位及 ROS 全功能验收。参数量减少与实际推理提速是两个结果，不能用前者代替后者。

结论限定于这两份已有 Engine 和本次部署条件；它不证明其他层、其他缩窄幅度或其他导出配置同样无效。

## 阶段结论

| 实验 | 完成的工作 | 最终成果 |
| --- | --- | --- |
| E1 | 80 类输出改为足球单类别，完成迁移、微调和独立 Val | 建立足球检测基线；相对 E0 明显提高 AP 和召回，同时明确低阈值误报代价 |
| E2 | 从 E1 初始化，缩窄第 19 层内部通道，完成迁移检查、恢复训练、独立 Val 和用户提供的 Orin 对照测试 | 总参数减少约 0.674%，整体 Val AP 接近 E1；当前 Orin 部署没有可测量加速收益 |

E2 完成了结构缩窄与恢复训练流程验证，但没有实现本轮实时性能改善目标。E1 继续作为部署性能对照基线，E2 保留为实验候选，不能以加速收益为由替换 E1。下一轮结构实验应先依据 Orin 上的实际耗时确定候选模块；如需归因精度变化，再补同预算、保持 E1 原结构的继续训练对照。

# E03 TensorRT性能剖析实验表

整理日期：2026-10-22。实机测量日期：2026-10-21。

| 项目 | 内容、产出与结论 |
| --- | --- |
| 实验定位 | 解释 E02 缩窄后没有提速的原因，定位GPU执行与系统路径瓶颈，为后续优化提供实测依据；属于性能诊断实验。 |
| 比较对象 | 已有E01/E02 TensorRT FP16 Engine；另在隔离目录为每模型构建performance和detailed候选，共四份Engine。复用原opset17 ONNX，没有重新训练或重新导出网络。 |
| 实验内容 | 原有/新performance Engine正常计时；原有与detailed逐层profile及模块归因；L19配对分析；传输与CUDA Graph诊断；Nsight Engine/检测器时间线；现场完整系统锚点。 |
| 实机环境 | Jetson Orin NX 16GB；JetPack 5.1.5、TensorRT Python 8.5.2.2；25W、GPU上限408 MHz、动态时钟，未锁频。 |
| 输入输出 | 固定双目batch=2；FP32输入 `[2,3,640,640]`、FP32输出 `[2,5,8400]`；FP16 tactics，one-to-many输出和外部NMS。 |
| 正常测速方法 | GPU常驻固定seed42输入，CUDA event包围执行并逐次同步；预热100次，每模型三轮、每轮60秒、交错执行；不挂layer profiler或Nsight。 |
| 原有 Engine 结果 | E01：mean/P50/P95/P99=28.13498/28.13542/28.17087/28.18651 ms；E02：28.27537/28.28502/28.33907/28.35631 ms，单位均为每batch2。 |
| 新performance交叉验证 | E01均值28.17795 ms，E02为28.22171 ms；约0.044 ms差异不足以支持结构加速。新旧图有构建差异，分组报告。 |
| L19局部结论 | 原有Engine三次profile均值合计1.36850→1.47933 ms，约增加8.10%；E01中该层仅占profile总时间4.80%，局部增量约70.2%来自辅助执行增长。 |
| GPU模块分布 | 原有E01 profile：Backbone扣除Attention约37.99%，Neck扣除内嵌PSA约21.41%，Attention约10.39%，Detect约14.15%，Reformat/Copy等辅助执行约16.05%。占比以profile层时间合计为分母。 |
| 执行组合证据 | 新detailed中观察到内部shape变化、tactic变化及额外Copy；未用强制tactic或硬件计数器A/B确定各因素因果贡献，不能只凭128→112断言通道不对齐。 |
| 重建一致性 | 固定64张Val，对每模型performance/detailed分别与其自身原有Engine比较，4组均通过；E01检测数43/43、最大匹配框差0.125 px，E02为44/44、最大分数差0.0002412。不是 E01/E02 检测完全一致，也不是全量AP测试。 |
| 检测器离线回放 | 无相机/ROS/双目融合/可视化，255次正常调用：整体58.986 ms；preprocess 9.475 ms、inference 29.594 ms、postprocess 13.547 ms、两图候选转CPU合计4.067 ms。方法墙钟含异步工作或等待，不当作纯CPU成本。 |
| NMS与同步发现 | 安装环境确认使用纯PyTorch NMS回退；Nsight检测器窗口中，目标应用无GPU活动间隔占约54.52%。它不代表整个GPU全局空闲，也不是正常延迟测量。 |
| CUDA Graph诊断 | 新E01 performance的单轮trtexec诊断：GPU Compute 28.5369→26.4055 ms（约−7.47%），enqueue 2.72675→0.101161 ms（约−96.3%）；尚不能写作生产路径或完整系统Hz提升。 |
| 完整系统锚点条件 | 仅E01一轮：100次预热、30秒、505帧对；VGA、相机100fps配置、发布调度上限50Hz、Viser开启、点云关闭、conf=0.45、top-k=5。 |
| 完整系统锚点结果 | processing=16.8124 Hz、publish=16.8122 Hz；cycle均值59.302 ms、P95=61.031 ms；读取开始→发布均值52.992 ms，不包含曝光与接收端消费。 |
| 系统结果解释 | 该单轮锚点未达到20/30/50 Hz；它不是新的E01/E02配对对照，不把与历史约16.49 Hz的场次差异认定为E03带来的加速。 |
| 主要产出 | 四份隔离Engine及一致性检查；完整正常计时和分位数、四份Top20、模块/L19 CSV、detailed tensor/tactic记录；Nsight原始包及分析；系统锚点、环境/模型指纹、分析脚本与完整报告。 |
| 归档与完成状态 | 已完成测量、原始文件回收、625项SHA256核验及本机CPU重算；回收时没有重新构建或测量。生产模型等12项文件/链接保持不变。 |
| 实验结论 | 原有及新构建组均未支持E02加速，L19局部反而变慢；主要GPU成本在Backbone、Neck与辅助执行，Attention不是第一成本组；系统路径存在值得优化的预处理、NMS、候选回传和同步开销。 |
| 对后续实验的作用 | 为E04提供后处理/数据驻留、同步和Graph的实施依据；诊断收益不等于已完成系统加速，E04实现与验收单独记录。 |

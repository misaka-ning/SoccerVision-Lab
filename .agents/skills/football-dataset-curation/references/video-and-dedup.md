# 视频提帧、去重与合并

## 有效范围和原始像素

先核验实际编码和内容；优先没有二次编码的干净源。MJPEG 原 AVI 每帧可独立解码，提取成 PNG 保留解码像素。将 H.264 MP4 转成 AVI/PNG不能恢复已有损失。图像保留原分辨率和颜色，模型输入的缩放不作用于最终训练图。

若用户只需数据集，有效范围可直接传给 helper，原视频不剪。若用户要求剪去 27:00 后：按实际帧率将结束时间转为帧边界（15 fps 的 [0,1620s) 是帧 0–24299），记录保留范围。MJPEG 可 `-c:v copy -frames:v 24300`，检查帧数、时长及保留包/像素一致；有音频则同时处理音频边界。帧间编码不能假定任意时间无损截断，应明确关键帧对齐或重编码造成的质量变化。同源 JSONL 按真实帧索引裁剪并验证对齐，不能按文件时间猜对应关系。保留原源或精确备份，避免不可恢复删除。

## prepare_frames.py

必填 `--video`、`--output`、`--layout mono|stereo`。`--output` 必须是不存在的新暂存目录，拒绝覆盖；脚本对输入只读。示例：

```bash
/opt/VisionStudio/runtime/bin/python <skill目录>/scripts/prepare_frames.py \
  --video /绝对路径/录像.avi --output /tmp/本次候选目录 \
  --layout stereo --sample-fps 2 --start 00:00 --end 27:00
```

时间支持秒数、MM:SS 或 HH:MM:SS，范围左闭右开。`--layout stereo` 将原图均分为 left/right；奇数宽度拒绝处理，不凭尺寸自行推断布局。`--sample-fps 0` 保留所有去重组代表。其他参数见 `--help`。

输出：

- `images/`：无框原生 PNG，含视频内容短哈希、源帧索引、eye；同内容同源帧稳定命名。
- `inventory.json`：每张图的源路径、索引、时间、eye、配对组、原生宽高及 PNG SHA256，供后续分类和合并。
- `frame-metrics.jsonl`、`dedup-groups.json`、`selection.json`：每帧比较值、分组、代表帧和保留理由；筛掉的是候选清单，原素材不删除。
- `previews/`：粗时间覆盖和保留图接触表；预览可以缩放并加帧号，不能作为训练图。
- `source.json`：源 SHA256、范围、参数、输出数量。脚本不赋四类标记、不写 label、不改目标数据集；运行完成后必须继续执行技能的逐图分类和自动足球标注步骤，确认无球的图片也创建零字节 label。

去重比较固定组锚点，不仅比较上一帧，避免相邻漂移积累。两目任一变化均保留这一时刻；组内优先清晰代表，再按默认约 2 fps 选代表组。默认缩略图 SSIM ≥0.90、平均像素差 ≤6、局部块差 ≤22 是本机起点，并非各种视频的固定真值；参数必须记录并按画面调整。

静止背景下小球的变化会被整体相似度稀释。可先从录像 JSONL/推理结果整理 ROI，传入 `--rois <json>`。ROI 文件结构如下，索引与输入视频一致，bbox 是**单目原生像素 xywh**：

```json
{"123": {"left": [[100, 90, 20, 18]], "right": [[94, 91, 19, 18]]}}
```

脚本比较当前/锚点 ROI 的原生像素变化；检测框缺失不等于 ROI 无变化。检查粗时间预览、去重组跨度、低分候选、球出现/消失及模糊/遮挡过渡，发现遗漏时传 `--keep-frames <json>`，文件为源帧索引列表，例如 `[123,124,188]`，运行到另一个新暂存目录。这些索引强制保留左右目，绕过代表采样。仅凭每秒粗预览不能证明没有短瞬间，必要时加密回看原视频或推理/检查组内帧。

## 全局去重和划分

对已有数据和多个新视频先做文件/解码像素精确哈希，再用感知哈希筛候选，并核验相似度和实际足球局部。仅 pHash 相近不够删除。保持小球位移、遮挡程度、模糊变化、负样本背景多样性；困难瞬间不因清晰度较低自动排除。

左右目视差图片是同一时刻的两个样本，不互相当重复丢掉。以帧对为选择单位；若一目与历史图重复，先审查整对再决定是否跳过整对，不能无说明破坏配对。跨片段重复记录对应对象/理由；已有人工数据保留，默认跳过新重复。

保持同帧左右目、同一静态去重组和相邻录像片段处在相同 split。新数据集按视频/连续片段组划分，不能对连续帧随机 8:1:1 后宣称独立验证。若只有单一连续来源，应说明当前验证局限，默认先加入 train，待独立来源补充 val/test。

## 合并验收

暂存完成分类及自动足球标注后，用本次明确文件清单追加；有球写框，确认无球写零字节 label，不能把提帧结束当作处理完成：

1. 保存 CSV/YAML 和会写入的 label 等基线/备份，检查重名、来源帧映射、split 及配对。
2. 新行按现有 CSV 字段顺序，缺少新字段时统一扩展表头，保留旧行原值/未知字段。已有图片和原 GT 字节不变。
3. 校验暂存：四项为 0/1、图片逐行对应、YOLO 格式/坐标/类别合法、空/缺失区分、审核状态符合事实；本次确认无球图片的对应 label 必须存在且为零字节。空 label + No Ball=0 或正框 + No Ball=1 为冲突，置审核而非自动修正人工值。
4. 检查基线哈希未改变，避免覆盖审核工具并发编辑；若改变，重读并重新合并。复制/写入新图片及 label 使用同目录临时文件和 `os.replace`，最后替换 CSV，保留回滚清单。
5. 跑 `scripts/validate_dataset.py --dataset <目录>`，复核新增/总数、旧图片/标注哈希、人工字段、YAML 路径及同组划分。脚本只读，校验通过不代表视觉标签已经人工确认。
6. 保存本次统计、参数、被排除列表及待审核清单。不需要重处理当前数据集才能创建或测试本 skill。
